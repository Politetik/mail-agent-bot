# 📬 Почтовый ИИ-агент для Telegram + Mail.ru

Telegram-бот, который читает вашу почту Mail.ru, разбирает деловую переписку и отвечает на вопросы —
текстом или голосом. Ищет телефоны и адреса, ведёт реестр договоров, показывает риски и то,
что ждёт вашего ответа.

```
Вы:  какой телефон у Анны Смирновой?
Бот: 📇 Контакт по запросу «Анны Смирновой»

     Анна Смирнова, руководитель отдела поставок — ООО «Ромашка»
     📞 +7 (916) 555-77-88
     📞 +7 (495) 123-45-67
     ✉️ a.smirnova@romashka.ru
     📍 125009, г. Москва, ул. Ленина, д. 10, офис 25
     🏢 ИНН 7701234567
```

## Две реализации

Функциональность одинаковая, база данных совместима — выбирайте по вкусу.

| | 🐍 Python (aiogram 3) | 🟢 Node.js |
|---|---|---|
| Папка | [`python/`](python/) | [`src/`](src/) |
| Запуск | `python -m app.main` | `npm start` |
| Инструкция | [python/README.md](python/README.md) | этот файл |
| Зависимости | `aiogram` | `imapflow`, `mailparser` |
| Тесты | 40 (pytest) | 52 (node:test) |

Не запускайте обе версии одновременно с одним токеном — Telegram разрешает
только один long polling (`409 Conflict`).

Дальше описана **Node-версия**; для Python-версии см. [python/README.md](python/README.md).

## Что умеет

| Возможность | Как это работает |
|---|---|
| Чтение почты | IMAP Mail.ru, инкрементально по UID — повторно письма не качаются |
| Разбор писем | ИИ + правила: тип (договор / переговоры / счёт / контакт), суть, контрагент, сумма, срок, статус, риски, просьбы |
| Контакты | ФИО, должность, компания, телефоны, e-mail, адрес, ИНН — с поиском по падежам («Анны Смирновой» → «Анна Смирнова») |
| Договоры | Реестр: номер, контрагент, сумма, срок, статус; одно упоминание в разных письмах = одна запись |
| Задачи | Что просят сделать и к какому сроку |
| Вопросы | «что по договору с Ромашкой?», «что висит на неделе?», «какие адреса есть?» |
| Голос | Голосовое сообщение → распознавание (Whisper) → тот же ответ |
| Без ключей ИИ | Полностью работает на правилах (телефоны, адреса, суммы, сроки) |

## Быстрый старт

**Требования:** Node.js **24+** (проверьте `node -v`), ящик Mail.ru, Telegram.

> Нужен Python вместо Node? См. [python/README.md](python/README.md) — там те же шаги.

### 1. Установить зависимости

```powershell
cd mail-agent-bot
npm install
```

> На Windows в PowerShell команда `npm` может быть заблокирована политикой выполнения.
> Тогда используйте `npm.cmd install` и `npm.cmd start`.

### 2. Создать конфиг

Быстрый способ — мастер, он спросит токен, почту и ключи и запишет `.env` (секреты не отображаются):

```powershell
scripts\setup-env.cmd
```

Или вручную:

```powershell
copy .env.example .env
notepad .env
```

### 3. Получить токен Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте токен вида `123456789:AAH...` в `.env`:

```
TELEGRAM_BOT_TOKEN=123456789:AAH...
```

### 4. Получить пароль приложения для почты

Обычный пароль от почты **не подойдёт**.

**Mail.ru**

1. Войдите в Mail.ru → **Настройки** → **Все настройки** → **Безопасность**.
2. **Пароли для внешних приложений** → **Создать пароль** (или «Добавить»).
3. Скопируйте выданный пароль (16 символов) в `.env`.
4. Там же проверьте, что включён доступ по IMAP:
   **Настройки** → **Почтовые программы** → «Разрешить доступ к почтовому ящику по протоколам IMAP/SMTP».

```
MAIL_USER=you@mail.ru
MAIL_PASSWORD=пароль_для_внешних_приложений
```

**Яндекс.Почта**

1. [id.yandex.ru](https://id.yandex.ru) → **Безопасность** → **Пароли приложений** → создать (тип «Почта»).
2. Яндекс.Почта → **Настройки** → **Почтовые программы** → включить «Разрешить доступ к почтовому ящику с помощью почтовых клиентов» (IMAP).
3. В `.env` замените хосты:

```
MAIL_USER=you@yandex.ru
MAIL_PASSWORD=пароль_приложения
MAIL_IMAP_HOST=imap.yandex.ru
MAIL_SMTP_HOST=smtp.yandex.ru
```

### 5. Подключить ИИ (опционально, но рекомендуется)

Без ключа бот работает на правилах — телефоны, адреса, суммы и сроки находит,
но пересказ переговоров будет сухим.

**DeepSeek** (дёшево, хорошо с русским): [platform.deepseek.com](https://platform.deepseek.com) → API keys → создать.

```
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
```

Подойдёт любой OpenAI-совместимый сервис: `openai`, `openrouter`, локальный `ollama` (без ключа).

### 6. Включить голос (опционально)

Нужен ключ OpenAI для Whisper (или свой сервер распознавания):

```
OPENAI_API_KEY=sk-...
```

### 7. Запустить

```powershell
npm start
```

### 8. Разрешить себе доступ

1. Напишите боту `/start` — он ответит «Доступ не настроен» и покажет ваш **chat_id**. Это нормально.
2. Впишите его в `.env`:

```
ALLOWED_CHAT_IDS=123456789
```

3. Перезапустите бота. Готово — нажмите «📥 Проверить почту».

> Белый список обязателен: бот читает вашу почту, посторонние не должны иметь к нему доступ.

### Автопроверка почты

Чтобы бот сам проверял ящик, добавьте в `.env`:

```
AUTO_SYNC_MIN=15
```

Тогда каждые 15 минут он будет забирать новые письма и присылать уведомление, если что-то пришло.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие, ваш chat_id, кнопки |
| `/sync` | Прочитать новую почту и разобрать её |
| `/digest 7` | Сводка за N дней: договоры, риски, ожидание ответа, задачи |
| `/contacts Анна` | Контакты с телефонами и адресами |
| `/contracts` | Реестр договоров |
| `/tasks` | Что висит и ждёт ответа |
| `/status` | Состояние подключений и базы |
| `/show 12` | Показать письмо № 12 целиком |
| `/help` | Справка |

Любой обычный текст — это вопрос агенту. Голосовое сообщение — тоже.

## Как это устроено

```
Telegram (long polling)
   │
   ├── текст ──────────────┐
   └── голос → Whisper ────┤
                           ▼
                   Интент + поиск по базе
                           │
              ┌────────────┴─────────────┐
              ▼                          ▼
     Контакты/договоры            Вопрос по переписке
     (детерминированно)           (LLM + фрагменты писем)
              │                          │
              └────────────┬─────────────┘
                           ▼
                     Ответ в Telegram

Mail.ru IMAP ──► парсер писем ──► анализ (LLM + правила) ──► SQLite (FTS5)
```

- **Инкрементальная синхронизация**: запоминается `UIDVALIDITY` и последний UID по каждой папке.
  Повторный `/sync` не перекачивает старое.
- **Два движка разбора**: LLM даёт структуру (тип, суть, риски, просьбы), правила гарантируют
  телефоны, адреса, ИНН, суммы и сроки. Результаты объединяются — ИИ не может «потерять» телефон.
- **Контакты отвечаются без ИИ**: номера и адреса нельзя галлюцинировать, поэтому они берутся
  напрямую из базы, с учётом падежей.
- **База**: SQLite + FTS5 с кириллицей, файл `data/mail-agent.db`. Полнотекстовый поиск,
  дедупликация писем, контактов и договоров.

### Схема данных

`emails` (письма + FTS-индекс) → `analyses` (разбор) → `contacts`, `contracts`, `tasks` (производные записи).
`sync_state` хранит позицию чтения, `meta` — служебные значения.

## Безопасность

- Бот работает **только на чтение**: он не отправляет и не удаляет письма.
- Доступ закрыт белым списком `ALLOWED_CHAT_IDS`; чужим бот показывает только их chat_id.
- `.env` с паролями не коммитится (см. `.gitignore`).
- База лежит локально в `data/`.
- ⚠️ Тексты писем отправляются в выбранный вами LLM-провайдер при разборе и ответах.
  Если это неприемлемо — используйте локальную модель (`LLM_PROVIDER=ollama`), тогда данные не покидают машину.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `AUTHENTICATIONFAILED` | Обычный пароль вместо пароля для внешних приложений, либо выключен IMAP. См. шаг 4. |
| Бот отвечает «Доступ не настроен» | Добавьте chat_id в `ALLOWED_CHAT_IDS` и перезапустите. |
| `409: Conflict` | Бот уже запущен в другом окне — закройте лишний процесс. |
| `ETIMEDOUT` / `ENOTFOUND` | Нет интернета или блокировка исходящих на 993 порт. |
| Ответы «без ИИ» | Не задан `LLM_API_KEY` — это работает, но кратко. |
| Голос не распознаётся | Нет `OPENAI_API_KEY` / `STT_API_KEY`. |
| Пустые ответы по почте | Ещё не было `/sync` или писем за `SYNC_DAYS`. |

## Запуск на сервере (VPS)

### Вариант 1: systemd

```bash
# на сервере, Node 24+
git clone <репозиторий> /opt/mail-agent
cd /opt/mail-agent/mail-agent-bot
npm ci --omit=dev
cp .env.example .env && nano .env
sudo cp deploy/mail-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mail-agent
journalctl -u mail-agent -f
```

### Вариант 2: Docker

```bash
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f
```

База хранится в томе `./data`, поэтому переживает перезапуски.

## Ограничения и что дальше

- Нет отправки писем (сознательно — чтобы бот не наделал дел).
- Вложения (PDF-договоры) пока не распознаются, учитываются только имена файлов.
- Один ящик на инстанс.
- Правила — эвристики; для сложных формулировок нужен ИИ-ключ.

Возможные шаги: OCR вложений, календарь дедлайнов, ежедневный дайджест по расписанию,
поддержка нескольких ящиков, экспорт реестра в Excel.
