# 🐍 Python-версия почтового ИИ-агента

Тот же бот, что и Node-версия, но на Python: **aiogram 3** для Telegram,
`imaplib` для Mail.ru, `sqlite3` для базы. Схема базы данных совместима —
можно переключаться между реализациями, не теряя историю писем.

Проверено на **Python 3.14.10** (Windows) и aiogram 3.31.

---

## Быстрый старт

### 1. Окружение

```powershell
cd mail-agent-bot\python

# Если команда `python` открывает Microsoft Store — используйте launcher:
py -3 -m venv .venv

# либо полный путь:
# C:\Users\<вы>\AppData\Local\Programs\Python\Python314\python.exe -m venv .venv

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Настройки

Конфиг берётся из `../.env` (общий с Node-версией) или из `python/.env` — второй приоритетнее.

Мастер сам спросит токен, почту и ключи (секреты вводятся без эха):

```powershell
..\scripts\setup-env.cmd
```

Или вручную: скопируйте шаблон и отредактируйте.

```powershell
copy ..\.env.example ..\.env
notepad ..\.env
```

Минимум для запуска:

```
TELEGRAM_BOT_TOKEN=123456789:AAH...
ALLOWED_CHAT_IDS=123456789        # узнать: написать боту /start, он покажет chat_id
MAIL_USER=you@mail.ru
MAIL_PASSWORD=пароль_для_внешних_приложений
LLM_API_KEY=sk-...                # опционально, но рекомендуется
```

Пароль Mail.ru создаётся в настройках: **Безопасность → Пароли для внешних приложений**.
Обычный пароль не подойдёт.

### 3. Запуск

```powershell
.\.venv\Scripts\python.exe -m app.main
```

### 4. Проверка без ключей

```powershell
.\.venv\Scripts\python.exe -m app.cli demo
```

Демо наполнит тестовый ящик (`python/data/demo.db`) и покажет сводку, поиск телефона,
договоры и задачи — Telegram и почта не нужны.

## Отправка писем

Бот умеет писать письма — но **никогда не отправляет без подтверждения**.

```
/send напиши Ивану, что договор подписан и счёт будет завтра
/reply 12 спасибо, всё получил, оплатим до пятницы
```

Что происходит:

1. Модель собирает черновик: получатель, тема, текст в деловом тоне.
   - адрес можно указать явно (`/send напиши на ivan@romashka.ru …`);
   - либо назвать человека — бот найдёт его в контактах из писем;
   - для `/reply 12` подставляются получатель, тема и заголовки треда (`In-Reply-To`).
2. Бот показывает карточку с кнопками **✉️ Отправить / ✏️ Переписать / ❌ Отмена**.
3. «Переписать» — напишите правки одним сообщением, черновик обновится.
4. После «Отправить» письмо уходит через SMTP, копия сохраняется в «Отправленные».

Настройки (`.env`):

```
SENDER_NAME=Дмитрий            # имя в подписи и заголовке From
EMAIL_SEND_ENABLED=true        # false — полностью запретить отправку
EMAIL_SEND_LIMIT_HOUR=10       # лимит писем в час на чат
```

Безопасность: адреса валидируются (до 5 получателей), контекст письма для ответа
проходит через санитайзер от prompt injection, отправка — только по нажатию кнопки
в чате из белого списка.

## Только входящие

Бот читает **только «Входящие»**. Отправленные письма не скачиваются и не попадают
ни в сводку, ни в проверку почты, ни в статистику:

```
MAIL_INCLUDE_SENT=false
```

Если в базе остались старые «Отправленные» — они удаляются командой:

```powershell
.\.venv\Scripts\python.exe -m app.cli purge-sent
```

Команда чистит папку, каскадно удаляет их разбор и пересчитывает треды.

⚠️ Побочный эффект: без «Отправленных» не работает отслеживание follow-up
(«молчат N дней») и обещаний из исходящих писем — для этого нужны исходящие.
Включается обратно одной строкой `MAIL_INCLUDE_SENT=true`.

Что считается рассылкой: маркетинг (скидки, промокоды, «поделитесь впечатлением»),
а также роботы без полезного содержания. **Транзакционные уведомления** — заказы,
доставка, счета, коды подтверждения, пароли — разбираются: в них бывает важная информация.
Пересчитать флаги после изменения правил: `python -m app.cli reclassify`.

## Обязательства и статусы тредов

`/tasks` показывает не абстрактные «задачи», а обязательства с направлением:

- **Я должен** — просьбы к вам и ваши обещания (входящие письма).
- **Жду от них** — обещания контрагентов и ваши просьбы (исходящие письма).
- **Молчат больше N дн.** — последним писали вы, ответа нет дольше `FOLLOW_UP_DAYS` (по умолчанию 3).

Данные хранятся в таблицах `commitments` (направление, текст, срок, статус) и `threads`
(агрегат переписки: когда последний вход/исход, сколько писем). Просроченные сроки
помечаются ⚠️. Уведомления роботов (`no-reply`, `mailer`, `agent`) обязательств не создают.

Алиасы Яндекс.Почты (`ya.ru` ↔ `yandex.ru`) распознаются как один ящик — иначе
исходящие письма считались бы входящими и направление обязательств путалось.

## Кнопки и навигация

Три слоя, чтобы не превращать чат в панель управления:

1. **Постоянная клавиатура** — 3 ряда, только частые действия:
   `📥 Проверить почту`, `📊 Сводка`, `📌 Что висит`, `📇 Контакты`, `⚙️ Ещё`.
2. **Контекстные inline-кнопки** — рядом с данными: в `/tasks` у каждого обязательства
   своя кнопка `✅ #12`; после сводки — «Обновить / Что висит»; после письма — навигация.
3. **Меню команд** (`setMyCommands`) — 9 команд с описаниями, видны по «/» и в кнопке меню.

Редкие разделы (договоры, статус, помощь, подсказка по `/show`) убраны в «⚙️ Ещё» —
постоянная панель не разрастается. Нажатие inline-кнопки перерисовывает текущее сообщение
(`editMessageText`), а не плодит новые.

## Голосовое управление

> **Сейчас отключено:** `STT_ENABLED=false` в `.env`. Бот не скачивает аудио и не грузит
> модель, на голосовые отвечает короткой подсказкой. Код сохранён — включение обратно
> это одна строка в конфиге.

Работает «из коробки»: локальный **faster-whisper**, без ключей и VPN. Первый запуск качает модель
(~460 МБ для `small`) в `data/models`, дальше — из кэша.

```powershell
# .env
STT_PROVIDER=local
STT_MODEL=small
STT_LANGUAGE=ru
```

**Замеры на этой машине** (Xeon 14 ядер, CPU int8, 7,3 с речи):

| Модель | Время | RTF |
|---|---|---|
| `small` | 4,1 с | 0,56 |
| `medium` | 12,2 с | 1,66 — медленнее реального времени, для CPU не подходит |

`large-v3` имеет смысл только на GPU (`STT_DEVICE=cuda`, нужны CUDA 12 и cuDNN 9).

### Команды голосом

Кнопки записи в интерфейсе бота нет: Telegram не позволяет ботам запускать запись,
микрофон открывает только клиент (удержание 🎤 в поле ввода).
Модель предзагружается при старте бота, поэтому первое голосовое обрабатывается
без задержки на инициализацию.

| Скажите | Что произойдёт |
|---|---|
| «проверь почту», «обнови ящик» | `/sync` |
| «сводка за неделю», «итоги за 3 дня» | `/digest` |
| «что висит», «обязательства» | `/tasks` |
| «контакты», «найди телефон Анны» | `/contacts` |
| «договоры» | `/contracts` |
| «покажи письмо 12» | `/show 12` |
| «закрой двенадцать» | подтверждение кнопками → `/done 12` |
| «статус», «помощь» | `/status`, `/help` |

Всё остальное — вопрос: «какой телефон у Соловьёва», «что по договору с Ромашкой».

Логика: сначала распознаём, показываем текст («🎤 Распознано: …»), затем роутер решает —
команда это или вопрос. Изменяющее действие (`закрой N`) выполняется только после нажатия
кнопки «✅ Закрыть».

Аудио не сохраняется: в базу попадает только распознанный текст.

## Защита от prompt injection
Письма — недоверенный ввод. Перед отправкой в модель текст проходит через `app/sanitize.py`:

- удаляются невидимые и bidi-символы, HTML-комментарии, длинные base64-блоки;
- строки с типичными инъекциями («ignore previous instructions», «игнорируй инструкции»,
  `<|im_start|>`, `[INST]`, `assistant:` и т.п.) заменяются на пометку об удалении;
- тело письма оборачивается в границы `<<<EMAIL … EMAIL>>>`, а системный промпт
  прямо запрещает выполнять инструкции из письма.

Каждое срабатывание пишется в лог с номером письма.

## Отличия от Node-версии

| | Python | Node.js |
|---|---|---|
| Telegram | aiogram 3 | свой клиент на fetch |
| Почта | `imaplib` (stdlib) | `imapflow` + `mailparser` |
| Зависимости | одна (`aiogram`) | две (`imapflow`, `mailparser`) |
| База | та же схема, `data/mail-agent.db` | та же схема |

Обе версии **нельзя запускать одновременно с одним и тем же токеном** — Telegram
разрешает только один long polling на бота (второй получит `409 Conflict`).

## Диагностика

| Симптом | Решение |
|---|---|
| `python` открывает Store | используйте `py -3` или полный путь к `python.exe` |
| `AUTHENTICATIONFAILED` | пароль для внешних приложений, не обычный |
| Бот молчит | добавьте chat_id в `ALLOWED_CHAT_IDS` |
| `409 Conflict` | уже запущена другая копия (или Node-версия) |
| Голос не работает | нет `OPENAI_API_KEY` / `STT_API_KEY` |
| Пустые ответы | не было `/sync` |
## Рендер Markdown в Telegram

Модель отвечает в Markdown, а Telegram не понимает его «как есть». Модуль
pp/telegram_format.py преобразует безопасное подмножество в HTML и экранирует всё
остальное — сообщение не может «не распарситься»:

- `## Заголовок` → **жирный**;
- списки `-`/`*` → `•`, цитаты `>` → `▎`;
- `**жирный**`, `*курсив*`, ` `код` `, `~~зачёркнуто~~` → соответствующие теги;
- `[текст](https://…)` → ссылка, небезопасные схемы → обычный текст;
- код-фенсы → `<pre>` с экранированием;
- длинный ответ режется на части ≤ 3800 символов **с закрытыми тегами** в каждой.

Если разметка получилась битой, срабатывает `to_telegram_plain` — читаемый текст без тегов.
Тесты: `python/tests/test_telegram_format.py` (14 кейсов).
